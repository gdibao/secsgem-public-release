# Security Policy

## Supported Versions

Security fixes are evaluated for the current `main` branch and the latest
published ComHub release. Older forks and unreviewed local modifications may
not receive a backport.

## Reporting a Vulnerability

Report vulnerabilities privately through the
[ComHub Security Advisory form](https://github.com/maheshenga/comhub/security/advisories/new).
Do not create a public GitHub Issue, discussion, pull request, or commit for a
security vulnerability before a fix has been coordinated.

Include a clear impact description, affected revision or deployment mode,
reproduction steps or a proof of concept, and any relevant non-sensitive logs.
Do not include access tokens, API keys, private keys, user data, or production
database exports.

## Scope

ComHub reviews reports affecting its maintained application code, self-hosted
deployment configuration, authentication and authorization boundaries,
commercial and billing integrations, and the current production release path.
Issues that require existing administrator access, only affect unsupported
local modifications, or have no practical impact may be out of scope.

## Disclosure

ComHub follows coordinated disclosure. Please allow maintainers time to
investigate and release a fix before publishing technical details.
